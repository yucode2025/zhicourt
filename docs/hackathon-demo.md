# 黑客松 3 分钟演示脚本 / hackathon-demo

## 演示流程

| 时间 | 动作 | 讲稿要点 |
|---|---|---|
| 0:00–0:20 | 首页 | “AI 很容易给出答案，但稀缺的是**理解、判断和证据意识**。我们把知乎的真实观点差异，变成一场知识审理。” |
| 0:20–0:50 | 输入「AI 会不会淘汰程序员」→ 发起审理 → 确认命题页 | “AI 先把模糊问题重写为**可审理的明确命题**，纯事实查询会被拒绝——这里只审理有争议的知识。” |
| 0:50–1:20 | 庭审页实时进度 | “并行检索知乎讨论与全网资料，36 条候选去重排序到 12 条来源；Evidence Agent 提取结构化证据——**事实、观点、数据、预测被明确区分**。” |
| 1:20–1:50 | 三栏庭审 + 点击证据 | “控辩双方只能引用**已存在的证据**（引用可点击追溯），Cross Examiner 自动发现逻辑问题——比如观点被当作事实、证据来源过于集中。” |
| 1:50–2:15 | 证据图谱页 | “每个结论都能沿 Source→Evidence→Argument→Verdict 完整追溯，这就是我们的 Evidence Engine。” |
| 2:15–2:40 | 返回庭审 →「我来质询 Judge」 | “用户不是旁观者。质询会被分类（事实/逻辑/证据/定义…），系统基于**现有证据**回应，不编造新证据。” |
| 2:40–3:00 | 《知识判决书》页 | “结论是**条件性判断**而非绝对答案：置信度、共识、分歧、最强反例、什么新证据会改变判决、下一步学什么。**ZhiCourt 不替你决定答案，而是让你看清答案如何被证据支撑。**” |

## 备份方案

| 风险 | 应对 |
|---|---|
| 实时创建卡住 | 直接打开历史案件 → 演示预置案件 |
| 现场无外网 LLM | 启发式演示模式（界面已标注），全流程可跑 |
| SSE 不动 | 刷新页面（事件已持久化，进度可恢复） |
